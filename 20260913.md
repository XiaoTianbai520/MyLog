1.学习了模板方法模式

当我们这样getBean的时候有一个问题就是当我们需要扩展新方法的时候很麻，需要手动在这个方法中加入

```
static class MyBeanFactory{
    public Object getBean(){
        Object bean = new Object();
        System.out.println("构造 " + bean);
        System.out.println("依赖注入 " + bean);
        System.out.println("初始化"+bean);
        return bean;
    }
}
```

改良后不管怎么注入新方法，都不用改变原有方法。

```
public class TestMethodTemplate {

    public static void main(String[] args) {
        MyBeanFactory beanFactory = new MyBeanFactory();
        beanFactory.addBeanPostProcessor(bean -> System.out.println("扩展方法1"));

        beanFactory.getBean();
    }


    // 固定不变的步骤作为方法
    static class MyBeanFactory{
        public Object getBean(){
            Object bean = new Object();
            System.out.println("构造 " + bean);
            System.out.println("依赖注入 " + bean);
            for (BeanPostProcessor beanPostProcessor : beanPostProcessors) {
                beanPostProcessor.inject(bean);
            }
            System.out.println("初始化"+bean);
            return bean;
        }
        private List<BeanPostProcessor>  beanPostProcessors = new ArrayList<>();

        public void addBeanPostProcessor(BeanPostProcessor beanPostProcessor){
            beanPostProcessors.add(beanPostProcessor);
        }
    }

    // 可扩展的作为接口
    static interface BeanPostProcessor{
        public void inject(Object bean);
    }
}
```

**模板方法核心思想：确定的功能放在方法中，不确定的功能，抽象成一个接口。**

2.普通类可以在@Bean注解修饰的方法参数中直接根据类型直接注入，String不行，需要用@Value（${}）声明配置文件中对应的环境变量直接注入

3.ApplicationContex的refresh方法封装了Bean的创建和后置处理器执行的过程

4.**AutowiredAnnotationBeanPostProcessor**的Bean后置处理器可以处理@Value和@Autowired注解

**CommonAnnotationBeanPostProcessor**可以处理@Resource @PostConstruct @PreDestory

**ConfigurationClassPostProcessor**可以处理@ComponentScan @Bean @Import @ImportResource



5.@Autowired和@Resource的区别：

@Autowired是优先根据类型注入，如果类型相同可用@Qualifier（）指定Bean名称
@Resource是根据字段名和Bean名称相等进行注入



6.这些东西都可以被抽象成 `Resource`：

- 本地文件
- classpath 下的文件
- URL 网络资源
- jar 包里的资源
- 内存中的字节数据
